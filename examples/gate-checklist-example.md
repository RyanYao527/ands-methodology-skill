# Gate Checklist 示例：Track 判定与 Gate 1-5 裁剪

> 对应验收 prompt：是不是所有任务都要过五道 Gate？这样会不会太重？

## 结论

不是所有任务都要完整走五道 Gate。ANDS 保留 Gate 思维，但通过 Quick / Standard / Enterprise Track 调整治理强度。裁剪的是检查强度和执行成本，不是责任本身。

## Track 判定示例

| 任务 | 建议 Track | 理由 | Gate 范围 |
|---|---|---|---|
| 修正文档中的一处说明错误 | Quick | 低风险、小范围、可快速回滚、不处理敏感数据 | 保留必要自检；Gate 1/3/4/5 可裁剪并记录理由 |
| 给内部系统增加导出周报功能 | Standard | 常规业务功能，有明确 Acceptance，需要机器质量和人验收 | Gate 1-5 默认执行 |
| 调整权限策略并影响多个角色 | Enterprise | 涉及权限、安全和跨角色影响，回滚成本更高 | Gate 1-5 加强，增加双人确认和回滚演练 |

## Gate 2 与 Gate 3 的边界

| 项目 | Gate 2 机器质量 | Gate 3 人验收 |
|---|---|---|
| 所有者 | AI / CI / 自动化检查 | 业务验收角色 / Project Owner |
| 检查对象 | 测试、lint、类型检查、构建、安全基线 | Acceptance 的业务结果 |
| 失败动作 | 修复后重跑，不提交人验收 | 返工或改写 Acceptance |
| 不应混入 | 业务满意度判断 | 代码风格、构建是否通过 |

## Quick 示例：文档说明修正

- Task ID: `DEMO-Q-001`
- Track: `Quick`
- 裁剪理由：只修改非敏感说明文本，不影响功能、权限、数据或发布流程。

| Gate | 处理方式 | 证据 | 失败动作 |
|---|---|---|---|
| Gate 1 需求准入 | 裁剪 | 变更说明中写明范围和风险 | 发现范围扩大则升级 Standard |
| Gate 2 机器质量 | 保留轻量检查 | Markdown 格式检查、链接检查或人工预览 | 修正后重查 |
| Gate 3 人验收 | 裁剪 | 修改者自检并请内容负责人抽查 | 争议内容退回确认 |
| Gate 4 发布审批 | 裁剪 | 随文档变更记录发布 | 发现影响外部承诺则升级 |
| Gate 5 复盘审计 | 裁剪 | 无复盘价值时在变更记录说明 | 如果暴露标准缺口则补 Lesson |

## Standard 示例：导出周报功能

- Task ID: `DEMO-WR-001`
- Track: `Standard`
- 适用理由：常规业务功能，有明确业务验收，需要 CI 与人验收。

| Gate | 处理方式 | 通过标准 | 失败动作 |
|---|---|---|---|
| Gate 1 需求准入 | 保留 | ANDS-T 字段完整；字段口径、权限边界和 Acceptance 明确 | 退回补齐任务卡 |
| Gate 2 机器质量 | 保留 | 自动化测试、lint、类型检查、构建、安全基线通过 | 修复后重跑，不进入 Gate 3 |
| Gate 3 人验收 | 保留 | 业务验收角色按 Acceptance 导出并核对结果 | 返修；必要时改写 Acceptance |
| Gate 4 发布审批 | 保留 | 发布说明、回滚口径、五资产快照完成 | 暂停发布并补证据 |
| Gate 5 复盘审计 | 保留 | Lessons 判断、知识回写、改进 Issue 完成 | 补齐后关闭 |

## Enterprise 示例：权限策略调整

- Task ID: `DEMO-E-001`
- Track: `Enterprise`
- 适用理由：涉及权限边界和多角色影响，属于安全敏感变更。

| Gate | 处理方式 | 加强点 | 失败动作 |
|---|---|---|---|
| Gate 1 需求准入 | 加强 | ANDS-T 必须附 ADR、角色矩阵和回滚口径 | 不进入执行；补齐决策记录 |
| Gate 2 机器质量 | 加强 | 权限负向回归、安全扫描、迁移检查全部通过 | 修复后重跑，必要时暂停任务 |
| Gate 3 人验收 | 加强 | 至少两个指定角色分别验证授权与拒绝场景 | 任一关键场景失败即 No-Go |
| Gate 4 发布审批 | 加强 | 发布负责人确认灰度、回滚和审计记录 | 暂停发布并补齐证据 |
| Gate 5 复盘审计 | 加强 | 必须形成 Lesson 或明确标准无需更新的理由 | 未完成不得关闭任务 |

## 使用规则

- Track 必须写进 ANDS-T。
- Gate 2 要检查 Track 是否低估风险。
- Quick 可以轻，但不能绕过安全红线。
- Standard 是 v0.1 的主线示例。
- Enterprise 只用于高风险任务，不把它当默认流程。
