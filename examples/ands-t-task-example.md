# ANDS-T 示例：内部系统导出周报功能

> 对应验收 prompt：帮我把“给内部系统加一个导出周报功能”写成 ANDS-T。

## Task Meta

- Task ID: `DEMO-WR-001`
- Title: `内部系统导出周报功能`
- Owner: `产品负责人`
- Track: `Standard`

## Goal

让授权用户能够按周导出内部系统的业务周报，用于例会前的数据核对和归档。

## Input

| 输入项 | 来源 | 说明 |
|---|---|---|
| 周报字段口径 | `[[Product/周报字段口径]]` | 定义导出文件必须包含哪些字段、字段名称和排序 |
| 当前筛选规则 | `[[Product/列表筛选规则]]` | 导出结果必须与页面筛选范围保持一致 |
| 权限说明 | `[[Decision/报表权限边界]]` | 只有拥有周报查看权限的角色可以导出 |
| 现有导出组件 | `[[Technical/导出组件说明]]` | 优先复用现有导出能力，减少重复实现 |

## Constraint

- 业务红线：导出数据口径必须与页面展示口径一致，不新增未经确认的统计口径。
- 技术限制：优先复用现有列表查询和导出组件，不重写报表体系。
- 安全限制：不得导出用户无权查看的数据；导出文件不包含敏感原始字段。
- 范围限制：本任务只支持按单周导出，不包含定时发送、跨周汇总或图表生成。

## Output

- 内部系统增加“导出周报”操作入口。
- 导出文件包含已确认的周报字段、字段顺序和文件命名规则。
- 权限不足、无数据、导出失败时提供可理解的页面反馈。
- 更新周报使用说明和 Gate 3 验收清单。

## Acceptance

> 这里只写业务可验证结果；测试、lint、构建和类型检查归 Gate 2。

- 授权用户选择任意一个自然周后，可以导出该周报表文件。
- 导出文件中的记录范围与页面当前筛选条件一致。
- 导出文件包含 `周起止日期`、`团队`、`事项名称`、`状态`、`负责人角色`、`本周进展`、`风险等级` 七类已确认字段。
- 无数据的周次不会生成误导性空报表，页面提示“当前周暂无可导出记录”。
- 无周报查看权限的用户看不到导出入口，且无法通过直接请求获得导出结果。

## Track

- Selected Track: `Standard`
- 选择理由：这是常规业务功能，影响授权用户的报表使用体验；需要机器质量检查和人按业务口径验收。它不直接触碰生产关键路径，也不改变权限模型本身，因此不升级为 Enterprise。

## Gate Requirement

| Gate | 是否需要 | 通过标准 | 失败动作 |
|---|---|---|---|
| Gate 1 需求准入 | 是 | Goal、Input、Constraint、Acceptance、Track 清楚；周报字段口径已确认 | 退回补齐字段口径或权限边界 |
| Gate 2 机器质量 | 是 | 自动化测试、lint、类型检查、构建和权限边界检查通过 | 修复后重跑，不进入 Gate 3 |
| Gate 3 人验收 | 是 | 业务验收角色按 Acceptance 逐条确认导出结果 | 返修；如验收口径变化则重写 Acceptance |
| Gate 4 发布审批 | 是 | 变更说明、回滚口径和五资产快照完成 | 暂停发布并补齐发布资产 |
| Gate 5 复盘审计 | 是 | Lessons 判断、知识回写和改进 Issue 完成或说明无需创建 | 补写复盘后再关闭任务 |
