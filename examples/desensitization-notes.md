# 示例脱敏说明

> 适用范围：`examples/` 下所有示例文件。目标是让示例可教学、可回归验收，同时不暴露真实组织、人员、仓库、网络地址、凭据、本地路径或业务敏感数据。

## 基本原则

- 示例优先使用合成任务，例如内部周报导出、文档修正、权限策略调整。
- 人员全部写成角色，例如 Project Owner、AI PM、业务验收角色、发布负责人。
- 项目名称使用泛化描述，例如内部系统、试点项目、演示任务。
- 链接使用抽象知识链接，例如 `[[Product/周报字段口径]]`，不写真实仓库、网页或本地路径。
- 数据只写字段类别和验收口径，不写真实客户、交易、财务、人事或生产数据。
- Gateway 和 Dashboard 可以作为 mock 展示字段，但必须声明 mock 边界。

## `data_class` 与脱敏三值的关系

这两组字段不是同一个分级轴：

- `data_class` 判断任务输入/上下文来自哪里：`synthetic`、`desensitized` 或 `Enterprise review`。
- `PASS / NEEDS_REDACTION / BLOCKED` 判断一条反馈或一个示例能否进入公开 examples、validation 或 release 材料。
- 一个任务可以标为 `desensitized`，但对应反馈仍可能是 `NEEDS_REDACTION`，因为它还保留了路径、截图、人员影子、仓库影子或业务细节。
- 一个反馈只有在三值判定为 `PASS` 后，才可进入公开 examples 或 validation；`NEEDS_REDACTION` 先改写再复核，`BLOCKED` 不进入发布包。

## 不得出现的信息类型

| 类型 | 处理规则 |
|---|---|
| 真实组织或公司名称 | 替换为团队、组织、内部系统、试点项目 |
| 真实人员姓名 | 替换为 Project Owner、业务验收角色、发布负责人等角色名 |
| 真实仓库或分支地址 | 替换为脱敏任务编号、交付记录或变更摘要 |
| 真实网络地址 | 不写具体地址；如需表达环境，写开发环境、测试环境、生产环境 |
| 本地绝对路径 | 不写机器、用户名、磁盘或目录结构 |
| 访问凭据 | 不写口令、密钥、访问令牌、数据库连接信息或会话内容 |
| 业务敏感数据 | 只保留字段类别、规则口径和合成样例 |
| 真实截图 | 只使用重制图、抽象表格或合成数据 |

## 脱敏三值判定

每个准备进入 examples、validation 或公开发布材料的反馈/样例，都要先给出一个保守判定：

| 判定 | 含义 | 允许动作 |
|---|---|---|
| PASS | 只包含合成材料，或已脱敏到无法识别真实人员、组织、仓库、域名、租户、凭据、本地机器、业务数据或项目细节 | 可进入 examples 或 validation |
| NEEDS_REDACTION | 存在可泛化的真实上下文，但仍能看到角色、项目、路径、截图、指标、聊天原文或业务细节的影子 | 先改写成角色、类别、合成字段或用户式 prompt，再复核 |
| BLOCKED | 包含凭据、token、会话内容、客户真实数据、租户配置、不可公开截图、可识别本地路径或无法安全泛化的业务事实 | 不进入发布包，只保留在本地审查记录或停止使用 |

红线扫描应至少检查：真实姓名、公司/组织名、仓库/分支、域名/IP、绝对路径、账号、密钥、OAuth、数据库连接、客户/交易/财务/人事数据、真实截图、原始聊天记录和可反推出来源的专有流程。

## 可保留的信息

- ANDS 概念名：ANDS-K、ANDS-T、ANDS-A、ANDS-W、ANDS-G。
- Track 名称：Quick、Standard、Enterprise。
- Gate 名称：Gate 1 到 Gate 5。
- 泛化工具类别：AI PM、Agent、CI、Dashboard、Gateway、知识库、执行记录。
- 非敏感检查类型：测试、lint、类型检查、构建、安全基线。
- 合成任务编号：`DEMO-WR-001`、`LSN-DEMO-001` 等。

## 示例改写规则

| 原始信息类别 | 示例写法 |
|---|---|
| 某真实功能名 | 内部系统导出周报功能 |
| 某真实负责人 | Project Owner 或业务验收角色 |
| 某真实交付记录 | `[[Release/DEMO-WR-001-周报导出发布记录]]` |
| 某真实缺陷 | 验收标准模糊导致返工 |
| 某真实环境 | 测试环境或生产环境 |
| 某真实指标 | 返工次数、Gate 一次通过率、知识回写及时率 |

## 种子用户反馈脱敏

v0.2 允许使用脱敏后的真实种子用户反馈。进入 examples 或 validation 前，先写入 `seed-user-feedback-intake-v0.2.md` 的 intake record，并完成以下转换：

- 原始语句改成用户式 prompt 或事实描述，不保留聊天原文。
- 真实组织、人员、仓库、域名、IP、本地路径、凭据和业务数据全部泛化。
- 保留可复现的误解类型，例如 Track 误判、Acceptance / Gate 2 / Gate 3 混淆、Gate 5 回写边界不清。
- 每条反馈必须生成一个 regression prompt，方便 Validation & Test Agent 回归。
- 如果无法脱敏到不可识别，反馈不进入发布包，只保留在本地审查记录中。

## 发布前自检

发布 examples 前至少检查：

- 是否错误暗示所有任务都必须完整走五道 Gate。
- Quick / Standard / Enterprise 的判定是否清楚。
- Gate 2 机器质量与 Gate 3 人验收是否分开。
- Acceptance 是否只写业务可验证结果。
- 是否出现真实组织、人员、仓库、网络地址、本地路径、凭据或业务敏感数据。
- 是否已经给出 PASS / NEEDS_REDACTION / BLOCKED 三值判定，并处理所有 NEEDS_REDACTION 或 BLOCKED 项。
- 是否把 v0.1 扩展成生产级 Gateway、Dashboard 或完整课程。
- 是否把真实种子反馈原文直接放入 examples 或 validation。

## 本轮示例脱敏结论

本轮 examples 使用合成任务和泛化角色；不包含真实项目细节。少量敏感类别词只出现在本说明和任务红线中，用于说明禁止范围，不代表存在真实敏感值。
