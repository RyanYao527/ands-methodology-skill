# Methodology 10 Models

## 定位

本 reference 用于快速调用 ANDS 十个方法论模型。重点是模型之间的逻辑链和产出边界，不写课程式长解释。

## 何时读取

- 用户要理解 ANDS 的完整思维框架。
- 用户要设计 Agent 分工、工作流、版本、治理或度量。
- 用户的请求跨多个标准，需要确认先后关系。
- 需要审查某个输出是否违背方法论口径。

## 核心规则/方法

### 十模型逻辑链

```text
研发 -> 团队 -> 知识 -> 文档 -> 任务 -> 调度 -> 工作流 -> 版本 -> 治理 -> 度量 -> 回写知识
```

### 模型速查表

| # | 模型 | 核心问题 | 常见输出 |
|---|---|---|---|
| 01 | 研发模型 | 人和 AI 如何分工 | 人机边界、责任声明、验收原则 |
| 02 | 团队模型 | PO、AI PM、Agent 如何协作 | L1/L2/L3 Agent 矩阵 |
| 03 | 知识模型 | 知识如何沉淀复用 | 8 大知识域、知识回写规则 |
| 04 | 文档模型 | 决策如何记录 | ADR、Reason、Alternative、Risk |
| 05 | 任务模型 | 任务如何让 AI 可执行 | ANDS-T 任务卡 |
| 06 | 调度模型 | AI PM 如何编排执行 | 拆解、分配、上下文、质检、重规划 |
| 07 | 工作流模型 | 需求如何走到发布与复盘 | 7 阶段流程、进入/退出条件 |
| 08 | 版本模型 | 发布到底快照什么 | Knowledge、Prompt、Architecture、Workflow、Code |
| 09 | 治理模型 | 质量如何被门禁保证 | Gate Checklist、Track 裁剪、失败动作 |
| 10 | 度量模型 | 如何证明和改进效能 | 效率、质量、成本、知识资产、人的状态 |

### 关键边界

| 易混点 | 正确口径 |
|---|---|
| AI PM Review vs 人验收 | AI PM Review 是过程质检；Gate 3 是人对业务结果验收 |
| AI PM vs Gateway | AI PM 决定拆什么、给谁、要什么上下文；Gateway 执行路由、注入、监控、限流 |
| Acceptance vs Gate 2 | Acceptance 是业务结果；Gate 2 是机器质量检查 |
| L1/L2/L3 Agent | L1 是角色，L2 是分工，L3 是具体工具或实例 |
| 版本 vs 代码 | 版本是五资产同步快照，不只是代码变更 |
| 度量 vs 汇报 | 度量是复盘和标准迭代输入，不是装饰性报表 |

### 使用顺序

1. 先用研发模型确认“人决策 + 验证，AI 执行 + 辅助分析”。
2. 再用团队模型确认角色与 Agent 分工。
3. 用知识、文档、任务模型定义输入资产和任务单元。
4. 用调度和工作流模型推动执行。
5. 用版本、治理、度量模型完成发布、复盘和标准迭代。

## 输出口径

管理者输出：

- 使用“逻辑链 + 决策点 + 风险点”表达。
- 强调组织责任、治理成本、人的负载和度量闭环。
- 避免进入工具参数或代码实现。

实践者输出：

- 使用“模型 -> 模板 -> 下一步动作”表达。
- 给出 Agent 矩阵、ANDS-T、ADR、Gate、Lessons 等结构化产物。
- 标明每个产物依赖哪些输入和由谁验收。

## 输出要求

- 不遗漏十模型，不把“十模型”写成“文件数量”。
- 每次跨模型输出都要显式说明模型顺序。
- 涉及复盘时必须回到知识模型和度量模型。
- 不扩展到 v0.1 之外的生产级平台建设。
